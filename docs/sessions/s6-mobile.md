# S6 モバイルアプリ: 指示書

ホスト用のアプリ(Expo)を作る。Web と同じアカウントで使い、アプリ限定の機能(通知・アラーム、オートメーション)を持つ。

## 読むもの

- `docs/sessions/common.md`
- `apps/mobile/AGENTS.md`(Expo は学習時点から大きく変わっている。書く前に SDK 57 の公式ドキュメントを読む)
- `docs/design.md` の 3.6、4.4、7.5、8 章
- `docs/research/mobile.md`(全体。特に 1〜6 章の推奨方針)
- `packages/core/src/schemas/automation.ts`(オートメーションの型、テンプレート)

## 担当の場所

`apps/mobile/` だけ。パッケージの追加は `apps/mobile` で `npx expo install <名前>`。

## 方針

- データは Supabase を直接読む(行レベルセキュリティで自分の行だけ見える)。予約の操作、外部予定の選択、接続先の登録など、サーバーの処理が要る操作は Web の API を呼ぶ(`EXPO_PUBLIC_API_URL`、`Authorization: Bearer <Supabase のアクセストークン>`)。API の一覧は設計書 8 章
- 型と検証、日時の表示は `@slotto/core`、色や余白は `@slotto/tokens` を使う
- 通知・アラームは端末のローカル通知で鳴らす(直近の予定だけを予約し、起動時とプッシュ受信時に張り直す)。オートメーションの実行はサーバー(S4)が行い、アプリは設定・結果の受信・履歴の表示を担う
- 通知の許可は、理由が伝わる場面で求める(初回起動時にいきなり求めない)

## 手順

### 1. 画面以外(デザインを待たずに進める)

1. 雛形のサンプル画面を片付け、Expo Router の構成を作る(ログイン、下のタブ: ホーム・カレンダー・予約ページ・オートメーション・設定)。中身は仮の表示でよい
2. Supabase のクライアントとログイン(メールのリンク、Google はブラウザ方式、開発用のデモユーザー)。セッションは暗号化して保存する
3. データの読み書きのフック(予約、反映中の外部予定、予約ページ、オートメーション、実行履歴、接続先、通知設定)
4. 通知とアラーム: expo-notifications のローカル通知、チャンネルの設計(`docs/research/mobile.md` の推奨)、張り直し、プッシュ通知のトークン登録(`/api/devices`)、通知をタップしたときの遷移(予定の詳細、会議 URL)
5. 型チェックとリントを通す。Expo Go で動く範囲を確かめ、development build が必要なものは最終報告に書く

### 2. 画面(デザインの方向が決まってから)

1. アプリの主要画面(ホーム、カレンダー、予定の詳細、オートメーションの一覧・作成・履歴、通知とアラームの設定)のモックを Claude Design で作る。`docs/design-brief.md` の 6 章「モバイルアプリ」「オートメーション」に従う
2. **ユーザーに見せて確認を取る**
3. 実装する。オートメーションはテンプレート(`AUTOMATION_TEMPLATES`)から始められ、「いつ」→「何をする」の順に組み立てられること
4. Android エミュレータか Expo Go で動かし、**ユーザーに画面を見てもらう**(スクリーンショットか、Expo Go で開く手順を示す)
