## できたこと

### サーバー側(`apps/web/src/server/calendar/`)

- Google カレンダー連携の OAuth(ログインとは別)。認可コードフロー + PKCE、`access_type=offline` + `prompt=consent`
  - スコープ: `openid` `email` `calendar.events` `calendar.calendarlist.readonly`。カレンダーのスコープが外されたら連携しない
  - state は `@/lib/crypto` で暗号化した値(誰の連携か、PKCE の verifier、戻り先、期限)。Cookie を使わないので、アプリがシステムのブラウザで開いても使える
  - refresh token / access token は `@/lib/crypto` で暗号化して `calendar_tokens` に保存。期限の 3 分前に更新。`invalid_grant` で接続を `needs_reauth` にする
  - `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` が無いとき: 連携ボタン(GET `/api/calendar/google/connect`)は戻り先へ `?calendar_error=not_configured` を付けて戻す。アプリ用の POST は 503 `not_configured`
- 同期(`syncConnection`)
  - カレンダー一覧を `external_calendars` に入れる。新しいカレンダーは、自分が書けるもの(owner / writer)だけ表示オンで入れる。祝日や他人の共有カレンダーはオフ。Google 側で消えたカレンダーは予定ごと消す
  - 表示オンのカレンダーの予定を、ユーザーのタイムゾーンでの今日 0 時から 90 日先まで、繰り返しを各回に展開して読み込み(`singleEvents=true`)、保存済みの行と突き合わせて新規・変更・削除の分だけ書き込む(調査の「案 W」。`sync_token` は使っていない)
  - 新しい予定は未選択。カレンダーの `auto_select_new` がオンなら「予定あり」の予定だけ選択済み(`selected_by='auto'`)、`external_series_selections` に当たる回は選択済み(`'series'`)
  - 変更は内容だけ更新し、選択の状態は保つ。期間にかかる予定のうち、外部に無くなったものは消す。期間より前の予定は残す
  - Slotto が書き込んだ予定(目印 `extendedProperties.private.slottoBookingId`、または `bookings.provider_event_id`)は取り込まない
  - 終日の予定はカレンダーのタイムゾーンの 0 時〜翌 0 時の時刻にする。「予定なし」と自分が辞退した予定は `is_busy=false`
  - 取り込む予定の種類は default / focusTime / outOfOffice(勤務場所・誕生日は外す)。保存するのはタイトル・場所・日時・状態・リンクだけ
- 予約の書き込み(`writeBookingEvent` / `updateBookingEvent` / `deleteBookingEvent`)
  - 予約ページの `write_calendar_id` のカレンダーへ書く。予定 ID は予約 ID から作る(再送しても二重にならない)。Slotto の目印を付ける
  - 場所が Google Meet なら `conferenceData.createRequest`(`requestId` は予約 ID から)で会議 URL を発行。準備中なら少し待って取り直す
  - ゲストを参加者に入れる。Google からの招待メールは送らない(`sendUpdates=none`。メールは Slotto から送る前提)
  - **書き込んだ予定の ID・カレンダー・会議 URL は `bookings`(`provider_event_id` / `provider_calendar_id` / `meeting_url`)に、この関数の中で保存する**
  - `updateBookingEvent`: キャンセル・辞退なら予定を消す。書き込み済みなら時刻などを合わせる。日程変更で新しい予約(`rescheduled_from` あり)が作られた場合は、元の予約の予定を新しい時刻に動かして引き継ぐ(会議 URL もそのまま)。未書き込みなら書き込む
  - 書き込み先が無い・接続が使えないときは何もしない(`writeBookingEvent` は null)
- 変更通知(events.watch)
  - 同期のあと、表示オンのカレンダーにチャンネルを張る(7 日)。期限の 1 日前に張り直すジョブを入れる
  - 受け口 `/api/webhooks/google-calendar` はチャンネルのトークンを照合し、30 秒の区切りでまとめた同期のジョブを入れる
  - `NEXT_PUBLIC_APP_URL` が https でなければ張らない(ローカルでは張らない)
- 定期の同期: 同期のあと、次の 6 時間の区切りの時刻に同期のジョブを入れる(同じ区切りは 1 件にまとまる)

### API

| エンドポイント | 内容 |
|---|---|
| `GET /api/calendar/google/connect?return_to=` | Web 用。Google の同意画面へ送る |
| `POST /api/calendar/google/connect` | アプリ用。本文 `{ return_to?: "slotto://...", login_hint? }`、`{ url }` を返す |
| `GET /api/calendar/google/callback` | 戻り先へ `?calendar_connected=1`(最初の同期に失敗したら `&calendar_sync=pending`)か `?calendar_error=<コード>` を付けて送る。コード: `not_configured` `denied` `invalid_state` `scope_missing` `no_refresh_token` `exchange_failed` |
| `POST /api/calendar/sync` | 本文 `{ connection_id? }`。接続ごとに `{ connection_id, status, added, updated, removed }` |
| `DELETE /api/calendar/connections/{id}` | 連携の解除。Google のトークンを取り消し、変更通知とジョブを止め、取り込んだ予定ごと消す |
| `PATCH /api/calendar/calendars/{id}` | 本文 `{ is_enabled?, auto_select_new? }`。表示オフでそのカレンダーの予定を消す、オンで読み込み直す |
| `POST /api/external-events/selection` | 本文は `eventSelectionInputSchema`。`apply_to_series` は「今後すべて」= 指定した回以降をまとめて変え、`external_series_selections` を追加・削除。変わった予定 `{ id, is_selected, selected_by }[]` を返す |
| `POST /api/external-events/seen` | 本文 `{ event_ids? }`。取り込み画面で見た印(未選択の新着から外す)。省くとすべて |
| `POST /api/webhooks/google-calendar` | Google からの変更通知 |

ホスト用の API はすべて `getApiUser` で本人を確かめる(Web の Cookie とアプリの Bearer の両方)。

### S4(実行基盤)が呼ぶ関数

`@/server/calendar` から:

- `runCalendarSyncJob(payload)` — kind `calendar_sync`。payload `{ connectionId, reason: "poll" | "push" | "manual" }`
- `runCalendarWatchRenewJob(payload)` — kind `calendar_watch_renew`。payload `{ calendarId }`

連携が切れている・接続が消えている場合は投げずに終える(再試行しても無駄なため)。それ以外の失敗は投げる。

ジョブの `dedupe_key` は `calendar_sync:<接続ID>:poll:<時刻>` / `calendar_sync:<接続ID>:push:<時刻>` / `calendar_watch_renew:<カレンダーID>:<期限>`。連携の解除では `cancelJobs("calendar_sync:<接続ID>:")` と `cancelJobs("calendar_watch_renew:<カレンダーID>:")` を呼ぶ。`enqueueJob` / `cancelJobs` が失敗(未実装を含む)しても、連携や同期そのものは止めずに警告のログだけ出す。
