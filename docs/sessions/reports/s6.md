### 4. 通知とアラーム(`src/features/notifications/`)

- **チャンネル**(Android。作った後は音・重要度を変えられないので先に固定):
  - `event-reminder` 予定の通知(重要度 HIGH)
  - `event-alarm` アラーム(重要度 MAX、アラームの音量、おやすみモードを突破する指定)。専用の音は未定。音を決めたら ID を変えて作り直す
  - `automation-result` オートメーションの結果
  - `booking-update` 予約が入った・キャンセルされた
- 通知のボタン: 会議 URL のある予定に「参加する」「詳細を見る」
- **予約の計画**(`plan.ts`、純粋な関数、単体テスト 7 件): 14 日先までの確定した予約と反映中の外部予定から、全体の初期値と予定ごとの個別設定に従って計画を作る。iOS の 64 件の上限に合わせ、近い順に 48 件まで。同じ分数の通知とアラームはアラームを優先。承認待ち・終日・時刻が過ぎたものは鳴らさない
- **張り直し**(`scheduler.ts`): いま予約されている通知と計画の差分だけを取り消し・予約する。起動時、前面に戻ったとき、プッシュを受け取ったとき、設定を変えたときに実行
- **許可**: 初回起動では求めない。通知・アラームの設定を変えたとき、オートメーションを作ったときに求める。拒否済みなら OS の設定を開く案内を出す
- **アラームの強さ**: iOS は `interruptionLevel: "timeSensitive"`(entitlement を app.json に宣言)、Android はアラーム用チャンネル + `SCHEDULE_EXACT_ALARM` の宣言
- **プッシュのトークン登録**: `POST /api/devices`。API が 404 / 405 / 501 を返す間は、`push_devices` に直接書く(行レベルセキュリティで許可されている)。ログアウト時は削除
- **タップしたときの遷移**: data の `{ type: "booking" | "external_event" | "automation_run", id }` で画面を開く。`{ type: "open_url", url }` と「参加する」ボタンは URL を開く。アプリが閉じていた状態からの起動にも対応(`useLastNotificationResponse`)
