# Slotto UI デザイン参考資料(調査メモ)

- 作成日: 2026-10-02
- 目的: 日程調整サービス「Slotto」(Web サイト + モバイルアプリ)の UI デザインを決めるための参考資料。依頼主の要望は「Slack などの仕事効率化アプリ・サイトを参考にした、洗練されたデザイン」。
- 調査方法: WebSearch / WebFetch によるテキスト情報の収集(公式ブランドガイドライン、デザインシステムの公開資料、デザイン解説記事、CSS の値など)。**画像・実画面は見ていない。** そのため「見た目の印象」に関する記述は、公開資料や解説記事の文章に基づく。
- 表記ルール:
  - 【事実】= 公開資料で確認できたこと(出典を付ける)
  - 【二次情報】= 公式ではない解説記事・まとめサイトに基づくこと(値が古い・不正確な可能性あり)
  - 【未確認】= 今回の調査では裏が取れなかったこと
  - 【提案】= 調査を踏まえた Slotto 向けの案(事実ではない)

## 1. Slack

### 1.1 アプリ UI の構造

【事実】2023 年 8 月 9 日発表の再設計(公式ブログ)で、ナビゲーションが次の構成に整理された。

| 領域 | 位置 | 中身 |
|---|---|---|
| ワークスペース切り替え | 最左端 | 複数ワークスペースのアイコン |
| タブ(レール) | 左端の細い縦列 | ホーム / DM / アクティビティ / 後で / その他。選ぶと右隣に「2 段目のサイドバー」が開く |
| サイドバー | レールの右 | チャンネル・DM・アプリの一覧。セクション(フォルダ相当)に自分で整理できる |
| 検索 | 画面最上部 | クリックすると背景の文脈を保ったまま検索 |
| 作成ボタン(+) | レール下部 | メッセージ・チャンネル・canvas・ハドルを 1 か所から作る |
| プロフィール | 左下 | 状態・通知・設定(Stanford 大の利用者向け案内による) |
| メッセージ面 | 中央 | 白地のコンテンツ領域。上にチャンネルヘッダー、下に入力欄 |
| スレッド面 | 右 | 必要なときだけ開く 3 列目 |

- 【事実】設計目標は「集中」。公式ブログは「情報をさらに整理し、重要な仕事に集中し、増え続けるツールにすばやくアクセスできる」ことを掲げている。
- 【事実】Slack Design の公式記事「A new visual language for Slack」は、この再設計で**情報密度は維持する**と明言している("we were committed to keeping all of the information density intact")。変えたのは質感のほうで、(1) グラデーションと半透明の面で軽さを出す、(2) ボタンとアバターの角丸を強め、罫線を弱める、(3) 高さ(elevation)と奥行きで UI の区画を分ける、の 3 点。
- 【事実】同記事によると、ナビ上の小さな通知シグナルを「Bloops」、タブにホバーすると中身を覗ける挙動を「Peeks」と呼んでいる。「移動しなくても中身が分かる」ことで画面遷移を減らす設計。
- 【二次情報】アプリの CSS を抜き出した公開 gist によると、メッセージ本文は `font-size: 15px` / `line-height: 1.46668`(約 22px)、送信者名は `font-weight: 900`、メッセージ行の内側余白は `8px 20px`。リアクションやボタンの角丸は `12px` または `4px`。
- 【二次情報】サイドバー幅 260px、スレッド面 340px、アバターは 36px の角丸四角(円ではない)という記述が非公式のまとめサイト(oh-my-design.kr)にあるが、同サイト自身が「209 項目中 0 項目が検証済み」と注記しているため**参考値止まり**。
- モバイル: 【事実】2020 年の刷新でハンバーガーメニューを廃止し、下部タブ(当時は ホーム / DM / メンション / 自分)に移行。右下に新規作成のフローティングボタンを置いた(Android Police、Neowin など)。2023 年以降のタブ名(ホーム / DM / アクティビティ / 検索 など)の現行構成は【未確認】。

### 1.2 配色の考え方

【事実】公式ブランドガイドライン(PDF、テキスト抽出で確認)の記述:

| 役割 | 名称 | HEX | 備考 |
|---|---|---|---|
| ブランド主色 | Aubergine(ナス色) | `#4A154B` | PMS 261 / RGB 74-21-75 |
| 主色の変化 | Aubergine (Null) | `#611F69` | Web のゼロ状態 |
| 主色の変化 | Aubergine (Active) | `#7C3085` | Web のホバー状態 |
| ロゴ色 | Blue | `#36C5F0` | |
| ロゴ色 | Yellow | `#ECB22E` | |
| ロゴ色 | Green | `#2EB67D` | |
| ロゴ色 | Red | `#E01E5A` | |
| アクセシブル代替 | Blue (Accessible) | `#1264A3` | 白地の青い文字リンク用 |
| アクセシブル代替 | Green (Accessible) | `#007A5A` | Web の成功状態用 |
| 黒 | Black | `#000000` | |

- 【事実】「ロゴ色はイラストやアイコンの差し色(pop colors)として使い、**文字や色面には使わない**」と明記されている。4 色は装飾専用で、UI の状態色には別の(コントラストを確保した)色を充てる、という二層構えになっている。
- 【事実】「この中核の色から外れたり、淡色(tint)を作ったりしない」とも書かれている。色数を絞り、主色の明度違い 3 段(`#4A154B` → `#611F69` → `#7C3085`)だけで状態変化を表す。
- 【計算値】白文字とのコントラスト比(WCAG 2.x の式で本調査が計算): `#4A154B` 14.0:1、`#611F69` 11.0:1、`#7C3085` 8.0:1、`#007A5A` 5.3:1。白地の `#1264A3` は 6.2:1。一方ロゴ 4 色は白地で 1.9〜4.7:1 しかなく、文字に使えないという公式ルールと整合する。
- 【事実】考え方としては「濃色のサイドバー = 常に同じ場所にある錨、白いコンテンツ面 = 作業場」。Slack Design の記事は Slack を「毎日座る机」に例え、テーマは個人のものだとしている。
- 【事実】テーマのカスタム入力は 9 個から 4 個に減らされた(公式記事)。4 つの名前は「System navigation / Selected items / Presence indication / Notifications」(テーマ配布サイト複数で一致。公式ヘルプは HTTP 429 で取得できず、名称は【二次情報】)。
  - 示唆: **サイドバーの色は実質 4 役割だけで決まる**(背景・選択中・在席・通知)。これ以上増やさないのが「うるさく見えない」理由の一つ。
- 【二次情報】ダークテーマの CSS 値(公開 gist): 背景 `rgb(26,29,33)`、文字 `rgb(209,210,211)`、ハイライト `rgb(29,155,209)`。純黒・純白を避けている。
- 【二次情報】アクセシビリティ面の批判もある。2023 年の再設計はコントラストを利用者が調整しにくいという指摘(Medium 記事)。色覚多様性向けテーマ(Protanopia、Tritanopia など)は用意されている。

### 1.3 書体

- 【事実】アプリ本体: `Slack-Lato`(Lato の自社配信版)。CSS は `font-family: Slack-Lato, Slack-Fractions, appleLogo, sans-serif`(公開 gist による)。Lato は SIL Open Font License。
- 【事実】ブランドガイドライン(旧版 PDF): 見出しは **Larsseit**、本文は **Circular Pro**。ブランド書体が使えない環境(Google ドキュメント等)の代替は **Proxima Nova**。ロゴタイプは「Hellix Bold」と PDF に記載(Larsseit とする二次情報もあり、版による違いの可能性。【未確認】)。
  - 見出し(Larsseit)の Web での字間: 小さい見出し `-1px`、大きい見出し `-2px`。
  - 本文(Circular)の Web での字間: 通常段落 `0px`、ヒーロー段落 `-0.2px`。
  - 大文字のみ・小文字のみは禁止。文頭だけ大文字(sentence case)かタイトルケース。
  - 見本の組み: H1 36/38、H2 24/28、H3 18/21、H4 12/15(サイズ/行送り)。**見出しの行送りはサイズの約 1.05〜1.25 倍と詰め気味**。
- 【事実】現行の slack.com(2026-10-02 に CSS を確認): 見出し `Salesforce-Avant-Garde`、本文 `Salesforce-Sans`、等幅 `Monaco, Menlo, Consolas`。**日本語ページは見出し `Tazugane-Info-Heavy`(たづがね角ゴシック Info)、本文 `NotoSansJP`**。つまり Salesforce 傘下になってからサイトの書体は Larsseit / Circular から入れ替わっている。
- 示唆: 「アプリは読みやすさ優先の人間味のあるサンセリフ、サイトの見出しは個性のある幾何学系」という**二層の使い分け**が Slack の一貫した方針。

### 1.4 角丸・余白・影

- 【事実】slack.com の CSS で使用頻度が高い角丸は `4px`(最多)、`1rem`(16px)、`8px`、`999px`(ピル)の順。ボタンは `4px` と小さめ。
- 【事実】slack.com のボタン: 高さの下限 42px、余白 `19px 40px 20px`、文字 14px・太字 700・字間 `0.057em`・大文字。主ボタンは塗り、副ボタンは白地に 1px の内側の線(ホバーで 2px)。
- 【事実】フォーカス表示は `outline: 2px dotted` + `outline-offset: 5px`。キーボード操作時の見え方を明示している。
- 【二次情報】アプリ内は 4px 単位の余白(4 / 8 / 12 / 16 / 20 / 24…)、カード・モーダルは 8px 角丸、影は弱め(`0 1px 3px rgba(0,0,0,.08)` 程度)でモーダルだけ強い、という記述(oh-my-design.kr、未検証)。
- 【事実】2023 年の再設計で「罫線を弱め、角丸を強め、elevation で区切る」方向に寄せた(公式記事)。線で囲むのではなく、面の色差と影で区切る。

### 1.5 アイコン・モーション

- 【事実】ロゴ(octothorpe)は「吹き出し」と「ひし形(lozenge)」の 2 つの基本形だけでできており、19×19 のグリッド上に組まれている。この 2 形状はグラフィック要素として取り出して使える(ブランドガイドライン)。30px 未満では 15×15 グリッドの小サイズ版を使う。
- 【未確認】アプリ内 UI アイコンの線幅・グリッドなどの仕様は公開資料が見つからなかった(社内デザインシステム「Slack Kit」は非公開)。
- 【事実】slack.com のボタンの遷移は `0.42s cubic-bezier(0.165, 0.84, 0.44, 1)`(ease-out-quart 相当)。色・影がゆっくり収束する動き。
- 【未確認】アプリ内のモーションの時間・イージングの公式値は公開されていない。oh-my-design.kr には 100 / 200 / 300ms の段階が載っているが、同サイト自身が「観測値ではない」と注記している。
- 【事実】動きの考え方としては Bloops(通知シグナル)と Peeks(ホバーでの覗き見)のように、**「状態が変わったことを小さく知らせる」「移動せずに確認できる」ための動き**に限っている(公式記事)。

### 1.6 マーケティングサイト(slack.com、日本語版を 2026-10-02 に取得)

【事実】セクションの並び:

1. ヘッダー: 機能 / ソリューション / エンタープライズ / リソース / 料金プラン。右上に「サインイン」「デモをリクエストする」「Slack を始める」
2. ヒーロー: 見出し 1 文 + 補足 1 文 + CTA 2 つ(「Slack を始める」「資料ダウンロード」)+ 製品 UI の動くカルーセル(用途ごとにタブで切り替え)
3. 導入企業ロゴの帯
4. 主要機能の紹介(用途カード 6 枚)
5. 新着情報(更新一覧 + 「すべての更新情報を見る」)
6. 4 本柱のセクション(Knowledge / People / Process / Platform)。各柱は「短い標語 + 3 つの小見出し + 数字 1 つ(例: 97 分、35%)+ 顧客の引用」
7. 導入事例(動画)
8. 数字で見る実績(90%、43 個、7 億通 など)
9. 関連リソース(ブログ・ウェビナー・ガイドのカード)
10. フッター直前の CTA(「Slack を始める」「デモをリクエストする」)
11. フッター(6 列のリンク集 + 地域切り替え)

読み取れる型:

- **見出しは短い断定文**(「すべての仕事を 1 か所で管理」「人間らしくつながる」)。機能名ではなく、利用者が得る状態を書いている。
- **CTA は同じ文言を 3 か所**(ヘッダー右上・ヒーロー・ページ末尾)に置く。主 CTA(塗り)と副 CTA(線)の 2 段構え。
- **製品画面は静止画ではなく「用途別に切り替わる UI」**として見せる。1 画面に全部を詰めず、用途ごとに 1 場面。
- **数字 + 引用**を各柱に 1 つずつ添える。
- 【事実】現行サイトの CSS 上の色: 主ボタン `#730394`(白文字とのコントラスト 9.7:1)、濃色面 `#481A54`、リンク `#0B5CAB`、文字 `#181818` / `#1D1D1D`、補助文字 `#5C5C5C`、淡色の背景面 `#F9F0FF` / `#FEF0F3` / `#FBF3E0` / `#EBF7E6` / `#EAF5FE`。**旧ガイドラインの `#4A154B` + 緑 CTA から、紫系 CTA に変わっている**(版による違い)。

### 1.7 ブランドガイドラインの要点(Slotto が守るべき線に直結する部分)

- 【事実】「自社サイトを作るときは自分らしく。**Slack の製品やサイトの見た目・雰囲気(look and feel)を模倣しないでください**。利用者の混乱や、Slack の推奨があるかのような誤解を招く」と明記。
- 【事実】Slack のロゴ・マーク・サイトの要素・ページのレイアウトを流用・ミラー・フレーム表示しない。
- 【事実】ロゴの禁止事項: 切り抜き、変形、透過度の変更、影などの効果、色の入れ替え、別書体での再現、縁取り、回転、octothorpe とロゴタイプの比率変更。
- 【事実】フルカラーのロゴは白・黒・ナス色の背景の上だけ。余白はロゴ横組みなら octothorpe 1 個分以上。
- 【事実】名称: 「Slack と連携する」と書くのはよいが、自社の製品名やドメインに "slack" を含めない。
- Slotto が Slack 連携機能を持つ場合は、連携を示す表記とロゴ使用のルール(Slack Brandfolder / メディアキット)を別途確認すること。【未確認: 最新版のガイドライン本文】

## 2. 同じ系統の仕事効率化ツール(Linear / Notion / Asana / Superhuman)

> この章の CSS の値は、各社の**公開サイト**の CSS を 2026-10-02 に取得して読んだもの(【事実: サイト CSS】)。ログイン後のアプリ本体の値とは一致しない場合がある。コントラスト比は本調査が WCAG 2.x の式で計算した【計算値】。

### 2.1 Linear

**事実(公式記事「How we redesigned the Linear UI (part II)」2024-03-28)**

- 再設計の目標は「視覚的なノイズを減らし、整列を保ち、ナビゲーション要素の階層と密度を上げる」こと。
- サイドバー・タブ・ヘッダー・パネルで、ラベル・アイコン・ボタンの縦横の位置を揃え直した。すぐには気づかないが「数分使うと感じる」種類の改善だと説明している。
- 配色は HSL から **LCH 色空間**に移行。テーマごとに 98 個の変数を定義していたのを、**基本色・アクセント色・コントラストの 3 変数**から自動生成する方式に変えた。LCH は知覚的に均等なので、同じ明度の赤と黄がほぼ同じ明るさに見える。コントラスト変数を上げるだけで高コントラストテーマも作れる。
- 文字と中立色アイコンを、ライトではより暗く、ダークではより明るくしてコントラストを上げた。chrome(枠まわり)の青みを減らし、「より中立で時代に左右されない」見た目にした。
- 見出しに Inter Display を採用して表情を足し、本文は Inter のまま。

**事実: サイト CSS(linear.app)**

| 項目 | 値 |
|---|---|
| 書体 | `"Inter Variable"`(`font-feature-settings: "cv01", "ss03"`、光学サイズ自動)、等幅 `"Berkeley Mono"`、セリフ見出し `"Tiempos Headline"` |
| ウェイト | 300 / 400 / **510** / **590** / 680(可変フォントの中間値を使う) |
| 本文サイズ | tiny 10px、micro 12px、mini 13px、small 14px(行間 1.5、字間 -0.013em)、regular 15px(行間 1.6、字間 -0.011em)、large 17px |
| 見出し | 17 / 20 / 24 / 32 / 40 / 48 / 56 / 64 / 72px。字間は -0.012em(小)〜 **-0.022em**(32px 以上)、行間は 1.4(小)〜 **1.0**(大) |
| 角丸 | 4 / 6 / 8 / 12 / 16 / 24 / 32px、ピル 9999px |
| ダーク背景 | 4 段階: `#08090A` → `#0F1011` → `#141516` → `#191A1B`(1 段あたり明度差はごくわずか) |
| ダーク文字 | 4 段階: `#F7F8F8` / `#D0D6E0` / `#8A8F98` / `#62666D` |
| ダーク罫線 | 白の 8% / 12% / 15%(`#FFFFFF14` など半透明) |
| ライト背景・文字 | 背景 `#FFFFFF` / `#F8F8F8` / `#F4F4F4` / `#F0F0F0`、文字 `#282A2F` / `#3C4149` / `#6F6E77` / `#86848D`、罫線 `#E9E8EA` |
| アクセント | `#7170FF`(ダーク)、ブランド面 `#5E6AD2` |
| 影 | 低 `0 2px 4px #0000001A`、中 `0 4px 24px #00000033`、高 `0 7px 32px #00000059` |
| 動き | 基本 `0.1s`、別枠で `0.18s`。イージングは ease-out 系(`cubic-bezier(.165,.84,.44,1)` など)を名前付きで定義 |
| レイアウト | ヘッダー高 64〜72px、背景 `#0B0B0BCC` + ぼかし 20px。ページ最大幅 1024px、左右余白 24px、12 列・列間 32px、本文の最大幅 624px |

**計算値(コントラスト比)**: ダーク背景 `#08090A` に対して 文字 1 段目 18.7:1、2 段目 13.6:1、3 段目 6.1:1、4 段目 3.5:1。ライトでは 14.4 / 10.3 / 5.0 / 3.7:1。**3 段目までが本文用(4.5:1 以上)、4 段目は補助・無効表示用**という使い分けが数値から読める。

**洗練されて見える理由(分析)**

- 色数が極端に少ない。背景 4 段・文字 4 段・アクセント 1 色で、区切りは半透明の細い線。
- 文字サイズの刻みが細かく(12 / 13 / 14 / 15px)、**13〜15px 中心の高密度**。大きな見出しほど字間を詰め、行間を 1.0 に近づける。
- 動きは 0.1〜0.18 秒と短く、出現は ease-out。待たせない。
- ウェイト 510 / 590 のような中間値で「太すぎない強調」を作る。

### 2.2 Notion / Notion Calendar

**事実: サイト CSS(notion.com。デザイントークンの接頭辞は `--tatami-`)**

| 項目 | 値 |
|---|---|
| 書体 | サンセリフ `NotionInter`(Inter の自社版)、セリフ `Lyon Text`、等幅 `iA Writer Mono`。製品 UI の再現部分には `ui-sans-serif, -apple-system, BlinkMacSystemFont, "Segoe UI", Helvetica, …`(OS 標準書体)のスタックも使われている |
| 日本語のセリフ代替 | `Georgia, YuMincho, "Yu Mincho", "Hiragino Mincho ProN", serif` |
| ウェイト | 400 / 500 / 600 / 700 |

**Notion Calendar(旧 Cron)**

- 【事実】製品ページの見出しは「It's time.」。訴求は「一目で予定が分かる(メニューバー)」「予約機能を内蔵」「タイムゾーンをまたいで働く」「モダンなデザイン(コマンドメニューとショートカット)」「12 言語対応」。CTA は冒頭と末尾の 2 か所。
- 【事実】タイムゾーンはカレンダーのグリッドの**すぐ左**に列として並ぶ。主タイムゾーンがグリッドに最も近い。デスクトップは最大 4 つ同時表示、名前を付け替えられ、`Z` キーで一時的に別のタイムゾーンへ「タイムトラベル」できる(公式ヘルプ)。
- 【二次情報】`M` / `W` / `D` で月・週・日を切り替え、`⌘K` でコマンドバー、`S` で空き時間の共有。空き時間の共有は、グリッド上で候補の時間帯をドラッグして選び、予約リンクか「候補日時の文章」を生成する方式(解説記事による)。
- 【未確認】予約ページ(ゲスト側)の画面構成の公式説明は、該当ヘルプページが 404 で取得できなかった。

**洗練されて見える理由(分析)**

- 純黒ではなく暖色寄りの黒(`#37352F`)と暖色グレー。紙のような柔らかさが出る。
- 色は青 1 色をアクションに限定し、他は淡い色面(パステル)を挿絵・カードの地にだけ使う。
- 余白 4px 刻み、角丸 4〜12px と控えめ。影より罫線と色面で区切る。
- Notion Calendar は「キーボードで全部できる」「メニューバーから会議に入れる」など、**速さそのものをデザインの一部**にしている。

### 2.3 Asana

- 【事実】公式ブランドページ: シンボル(3 つの点)は常にコーラル色、ワードマークは明るい背景で黒・暗い背景で白。余白はシンボルの高さ分。禁止: 旧ロゴの使用、色の変更、影などの効果、シンボル単独使用、副次色の背景への配置。**「Asana の視覚的アイデンティティの独特な見た目・雰囲気を模倣するもの」を避ける**こと、他社の商標・ロゴ・製品名・ドメイン・アバターに Asana のブランド資産を使わないこと、と明記。
- 【事実: サイト CSS(asana.com)】欧文は `"TWK Lausanne", "Helvetica Neue", Helvetica, sans-serif`。**日本語は `"Hiragino Kaku Gothic ProN", "Helvetica Neue", Helvetica, sans-serif`(Web フォントを読み込まず OS の書体に任せている)**。頻出色は `#F06A6A`(コーラル)、`#0D0E10`(ほぼ黒)、`#F6F8F9`(淡いグレー面)、`#151B26` / `#222B37`(濃紺の面)、`#646F79`(補助文字)、`#796EFF`(紫)。角丸は `3px` が最多。動きは 150 / 225 / 300ms。
- 【二次情報】見出し書体は Ghost(Sharp Type)、本文は TWK Lausanne のウェイト 300(shadcn.io の抽出による)。
- 【計算値】白 on コーラル `#F06A6A` = 3.0:1(本文には不足)。黒 `#0D0E10` on コーラル = 6.4:1。**コーラルは「シンボルと差し色」で、文字を載せる面には使いにくい色**であることが分かる。
- 洗練されて見える理由(分析): 暖色のコーラルは点・小さな差し色に限り、面はほぼ黒と白と淡いグレー。角丸 3px と小さく、線が細い。日本語は無理に Web フォントを当てず OS 書体で軽さを優先している。

### 2.4 Superhuman

- 【事実】公式ブログ「game design, not gamification」(Rahul Vohra)の 7 原則: (1) 具体的で達成可能な目標(Inbox Zero)、(2) 細やかな感情の設計、(3) **すばやく確実な操作**(キー入力を取りこぼさない)、(4) 楽しい「おもちゃ」を作る(例: 「3D」と打つと「3 日後」に展開される日時の自動補完)、(5) **次の行動を明白にする**(アーカイブしたら次のメールが出る)、(6) 邪魔のない即時のフィードバック(`⌘K` で操作しながらショートカットを覚えさせる)、(7) 技能と難度の釣り合い。
- 【二次情報】「すべての操作を 100ms 以内」を掲げ、内部目標は 50〜60ms とされる(デザイン解説記事・ポッドキャストの要約による。公式の数値としては【未確認】)。
- 【事実: サイト CSS(superhuman.com)】書体は自社の `"Super Sans VF"` / `"Super Serif VF"` / `"Super Sans Mono VF"`。余白は 4px 基準(1 / 2 / 4 / 6 / 8 / 10 / 12 / 16 / 20 / 24 / 28 / 32…)、角丸は 2〜64px のトークン + ピル。色は紫と「mulberry」系の濃色(`#1B1938`、`#2D2A5C`、`#353088`、淡紫 `#D4C7FF`)。CSS の `light-dark()` 関数でライト・ダークを同時定義している。動きは 0.3〜0.4 秒が中心(サイトは演出寄り)。
- 【事実】2026-10 時点の superhuman.com は自らを「AI productivity suite」と説明しており、メール単体の製品サイトではなくなっている(メタ説明文)。以前のメールアプリの UI 仕様(書体・配色)は【未確認】。
- 【計算値】白 on `#1B1938` = 16.9:1、淡紫 `#D4C7FF` on `#1B1938` = 10.8:1。
- 洗練されて見える理由(分析): 見た目より**応答の速さと「次に何をするか迷わせない」流れ**が上質さの正体。日程調整なら「日付を選んだら時間が出る、時間を選んだら確認が出る」を待ち時間なしでつなぐことに相当する。
