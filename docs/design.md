# Slotto 設計書

- 版: 0.1(2026-10-02)。リサーチ結果(`docs/research/`)が揃ったら 0.2 に更新する
- 関連: [実装計画](plan.md) / [デザイン方針](design-brief.md)

## 1. 概要

Slotto(読み: スロットー)は、空き時間を共有して相手に予約してもらう日程調整サービス。TimeRex の機能と流れを参考にする。名称・ロゴ・文言・画像・コードは写さない。

| 提供形態 | 役割 |
|---|---|
| Web サイト | 主役。紹介サイト、ホストの管理画面、ゲストの予約ページ |
| モバイルアプリ(iOS / Android) | ホスト用。Web と同じアカウントで使う。アプリ限定機能あり |

### Slotto 独自の機能(TimeRex との違い)

1. **選んだ予定だけ反映**: Google カレンダーなど外部の予定を 1 件ずつ選び、選んだ予定だけを Slotto に表示して空き時間の計算に使う
2. **通知・アラーム(アプリ限定)**: 予定の時間が近づいたら通知やアラームを鳴らす
3. **オートメーション(アプリ限定)**: 予定の時間になったら決めた操作を自動で行う。登録した API を呼ぶ、AI にタスクを実行させる、など

## 2. 用語

| 用語 | 意味 |
|---|---|
| ホスト | アカウントを持ち、予約を受ける人 |
| ゲスト | 予約する人。ログイン不要 |
| 予約ページ | ゲストが日時を選ぶページ。TimeRex の「日程調整カレンダー」に相当 |
| 予約 | ゲストが確定(または申請)した 1 件の予定 |
| 外部予定 | Google カレンダーなど、連携先から読み込んだ予定 |
| 反映 | 外部予定を選んで Slotto に取り込むこと。反映した予定は Slotto のカレンダーに表示され、その時間は予約を受け付けない |
| オートメーション | 「いつ(トリガー)」「何をする(アクション)」の組み合わせ |
| 接続先 | オートメーションが呼ぶ外部 API や AI の設定 |

### 3.4 ゲストの予約フロー

1. 予約ページの URL を開く(ログイン不要)
2. 日付を選ぶ → 時間枠を選ぶ(タイムゾーンを表示)
3. 名前・メール・質問への回答を入力する
4. 完了画面。カレンダーに追加するリンクと .ics、変更・キャンセル用のリンクを表示する
5. 確認メールが届く(承認制の場合は「申請を受け付けました」→ 承認後に確定メール)
6. メールのリンクから日程変更・キャンセルができる

## 5. システム構成

```
ゲスト(ブラウザ) ─┐
ホスト(ブラウザ) ─┼─▶ Web: Next.js(Vercel) ──▶ Supabase(Auth / Postgres)
ホスト(アプリ)  ─┘        │   ▲                      │
   │ Supabase を直接読む    │   │ 毎分呼び出し          │ pg_cron
   └──────────────────────┼───┴──────────────────────┘
                           ▼
        Google Calendar / メール送信 / Expo Push / AI / Webhook 先
```

| 層 | 技術 |
|---|---|
| リポジトリ | pnpm ワークスペース |
| Web | Next.js(App Router)、TypeScript、Tailwind CSS v4、shadcn/ui |
| アプリ | Expo(React Native)、Expo Router |
| 共有ロジック | `packages/core`(空き枠の計算、型、入力検証) |
| デザイントークン | `packages/tokens`(Web とアプリで同じ値を使う) |

| メール | Resend(.ics 添付) |
| プッシュ通知 | Expo Push Service |
| AI | AI SDK。モデルは設定で差し替えられるようにする |
| ホスティング | Vercel |

## 6. データモデル

正は `supabase/migrations/` の SQL。ここは概要。すべての表に行レベルセキュリティをかけ、ログイン中のユーザーは自分の行だけ読める。ゲスト向けの画面と API は、サーバー側で必要な項目だけを取り出して返す(匿名ユーザーには表を直接読ませない)。

| 表 | 内容 |
|---|---|
| `profiles` | ユーザー名、表示名、タイムゾーン、プラン |
| `calendar_connections` | 外部カレンダーの接続(提供元、アカウント、状態) |
| `calendar_tokens`(非公開) | 接続のトークン。暗号化して保存し、サーバーだけが読む |
| `external_calendars` | 接続内のカレンダー。表示のオン・オフ、新着の自動反映、同期の状態 |
| `external_events` | 読み込んだ外部予定。`is_selected` が反映の有無 |
| `external_series_selections` | 「この繰り返しは今後すべて反映」の指定 |
| `booking_pages` | 予約ページの設定。受付時間とフォーム項目は JSON |
| `booking_page_candidates` | ホストが手で選んだ候補日時 |
| `bookings` | 予約。ゲスト情報、回答、状態、管理用トークン、書き込んだ外部予定の ID |
| `scheduled_jobs` | 時刻指定の実行待ち(リマインド、通知、オートメーション、同期の更新) |
| `automations` | トリガーとアクション |
| `automation_runs` | 実行履歴と結果 |
| `api_connections` | 接続先(Webhook、AI)。秘密の値は非公開の表に暗号化して保存 |
| `push_devices` | アプリのプッシュ通知トークン |
| `alarm_settings` | 通知・アラームの初期値と、予定ごとの個別設定 |

`bookings` には、同じホストの有効な予約どうしの時間が重ならないようにする排他制約(exclusion constraint)をかける。同時に 2 人が同じ枠を押しても、片方だけが通る。

## 7. 主要ロジック

### 7.1 空き枠の計算(`packages/core`)

入力は、予約ページの設定、ふさがっている時間帯の一覧、対象期間、現在時刻。出力は予約できる枠の一覧。外部への通信をしない純粋な関数にして、単体テストで固める。

ふさがっている時間帯 = 有効な予約(前後の空きを含む)+ **反映中の外部予定**。選んでいない外部予定は計算に入れない。

枠を出す手順:
1. 対象期間の各日について、受付時間(曜日の設定と日付指定の例外)をホストのタイムゾーンで実際の時刻に直す
2. 祝日を除外する設定なら、その日を除く
3. 枠の刻みごとに開始時刻を並べる
4. 受付期限(何時間前まで、何日先まで)から外れる枠を除く
5. ふさがっている時間帯と重なる枠を除く
6. 1 日の上限に達した日を除く

### 7.2 予約の確定

1. サーバーで空き枠を計算し直し、選ばれた枠がまだ空いていることを確かめる
2. `bookings` に書き込む。排他制約に当たったら「この枠は埋まりました」と返す
3. Google カレンダーに予定を書き込み、Meet の URL を受け取る
4. 確認メールを送る。リマインド、通知、オートメーションの実行予定を `scheduled_jobs` に入れる

### 7.3 外部予定の同期と反映

1. 接続時と定期的に、差分だけを読み込んで `external_events` を更新する
2. 新しい予定は未選択で入る。カレンダーの「新しい予定を自動で反映」がオン、または繰り返しの「今後すべて」に当たる場合は選択済みで入る
3. 外部で変更された予定は内容を更新し、選択の状態は保つ
4. 外部で削除された予定は削除する
5. Slotto が書き込んだ予定には目印を付け、読み込みの対象から外す

### 7.4 時刻指定の実行

`scheduled_jobs` に実行時刻と内容を入れておく。pg_cron が毎分、Web の内部 API を呼ぶ。内部 API は時刻が来たジョブを取り出して実行し、結果を記録する。失敗は間隔を空けて再試行する。予約の変更・キャンセル時は、対応するジョブを取り消して入れ直す。

### 7.5 オートメーションのアクション

| アクション | 実行場所 | 内容 |
|---|---|---|
| 通知・アラーム | サーバー → 端末 | プッシュ通知を送る。端末側でもローカル通知を予約しておく |
| API を呼ぶ | サーバー | 登録された URL に JSON を送る。署名を付ける。内部ネットワーク宛ては拒否する |
| AI に実行させる | サーバー | 指示文に予定の情報を埋め込んで AI に渡し、結果を履歴に保存して通知する |

指示文や送信内容には `{{予定のタイトル}}` のような差し込みを使える。

## 8. API

Web の画面はサーバー側で Supabase を直接読む。アプリは、自分の行の読み書きは Supabase を直接使い、サーバーの処理が要る操作は下の API を呼ぶ(Supabase のログイン情報を付ける)。

| 区分 | エンドポイント | 内容 |
|---|---|---|
| 公開 | `GET /api/public/pages/{username}/{slug}` | 予約ページの公開情報 |
| 公開 | `GET /api/public/pages/{username}/{slug}/slots` | 空き枠 |
| 公開 | `POST /api/public/bookings` | 予約の作成 |
| 公開 | `GET /api/public/bookings/{token}` | 予約の確認 |
| 公開 | `POST /api/public/bookings/{token}/cancel` `…/reschedule` | キャンセル、日程変更 |
| ホスト | `GET /api/calendar/google/connect` `…/callback` | Google 連携 |
| ホスト | `POST /api/calendar/sync` | 同期の実行 |
| ホスト | `POST /api/external-events/selection` | 外部予定の選択・解除(複数件) |
| ホスト | `POST /api/bookings/{id}/approve` `…/decline` `…/cancel` | 予約の操作 |
| ホスト | `POST /api/connections` ほか | 接続先の登録(秘密の値を含むため) |
| ホスト | `POST /api/automations/{id}/test` | オートメーションの試し実行 |
| ホスト | `POST /api/account/delete` | アカウント削除 |
| 内部 | `POST /api/internal/dispatch` | 時刻が来たジョブの実行(共有シークレットで保護) |
| 内部 | `POST /api/webhooks/google-calendar` | Google からの変更通知 |

## 9. セキュリティとプライバシー

- 行レベルセキュリティで、自分の行だけ読み書きできるようにする
- 外部カレンダーのトークンと接続先の秘密の値は、暗号化して非公開の表に置く
- ゲストの変更・キャンセル用リンクは、推測できない長いトークンにする
- 公開 API には回数制限をかける
- Webhook は送信先を検査し、内部ネットワーク宛てを拒否する
- 外部予定は、反映に必要な項目(タイトル、日時、場所)だけを保存する
- Supabase の公開鍵の名前は `…_SUPABASE_PUBLISHABLE_KEY` に統一する

## 10. 表示と文言

- 日本語を先に作る。文言は 1 か所にまとめ、後で英語を足せるようにする
- 日時はホストとゲストそれぞれのタイムゾーンで表示する
- スマホ幅でも予約ページが使いやすいこと(ゲストはスマホで開くことが多い)
- ライトとダークの両方に対応する

## 11. ユーザーに用意してもらうもの

開発はローカルの Supabase(Docker)で進められる。本番につなぐ段階で次が必要になる。

| もの | 用途 |
|---|---|
| Supabase のプロジェクト | 本番の DB と認証 |
| Google Cloud の OAuth クライアント | Google ログインとカレンダー連携。公開には Google の審査が必要 |
| Resend のアカウントと送信用ドメイン | メール送信 |
| Vercel のプロジェクト | Web の公開 |
| ドメイン | サイトの URL、メール、アプリを開くリンク |
| AI の API キー | 「AI に実行させる」アクション |
| Apple Developer / Google Play の開発者登録 | アプリの配布 |
