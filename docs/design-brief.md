# Slotto デザイン方針

デザインを作るセッションと、画面を実装するセッションの共通の前提。機能と画面の一覧は [設計書](design.md) の 3 章と 4 章にある。

## 1. 依頼主の要望

- Slack などの仕事効率化アプリ・サイトを参考にした、洗練されたデザイン
- Claude Design を積極的に使う
- モックができたら、その都度見せて確認を取る

## 2. 狙う印象

「毎日開く仕事道具」として信頼できること。落ち着いていて、密度があり、迷わない。装飾で目を引くのではなく、整った余白と書体と色の使い分けで洗練を出す。

| 狙う | 避ける |
|---|---|
| 濃色のサイドバーと明るい作業面の対比 | 画面全体が白くてのっぺりした管理画面 |
| 主色 1 色を要所だけに使う | 紫のグラデーション、多色づかい |
| 細い罫線と控えめな影 | 浮いたカードの多用、強い影 |
| 情報の密度はあるが、行間と余白で読みやすい | 余白だらけで 1 画面の情報が少ない |
| 短く具体的な日本語の文言 | 英語の直訳、絵文字の多用 |
| 状態の変化が分かる小さな動き | 意味のない大きなアニメーション |

## 3. 参考にするものと、写さないもの

参考にするのは構造と作法。Slack、Linear、Notion Calendar、Superhuman など。調査結果は `docs/research/ui-references.md` にある。

- 参考にする: 画面の骨組み(サイドバー、一覧と詳細の 2 面)、密度、書体の階層、色の役割分け、空の状態の見せ方、キーボード操作への配慮、紹介サイトでの製品画面の見せ方
- 写さない: Slack のナス色と 4 色ロゴ、各社のロゴ・アイコン・イラスト・文言、TimeRex の画面そのもの

## 4. ブランド

- 表記: サービス名「Slotto」、ロゴ「slotto」(すべて小文字)
- ロゴの方向: 2 つ並んだ「t」を予約枠に見立てる、最後の「o」を時計やカレンダーに見立てる、など。日程調整のサービスだと一目で伝わること(カタカナの「スロット」から連想される遊技機の印象を避ける)
- アプリアイコンは、ロゴの要素を 1 つ取り出した単純な形

## 5. 色と書体

最初の確認で、方向の違う案を 2〜3 個並べて選んでもらう。

- 色: 濃色のサイドバー色、主色(ボタンや選択中の表示)、状態の色(成功・注意・危険・情報)、予約ページの色分け用の 6〜8 色。文字と背景のコントラストは WCAG AA 以上
- ライトとダークの両方を定義する
- 書体: 和文と欧文の組み合わせ。Web フォントとして読み込める、ライセンス上問題のないもの。数字は等幅(時刻の桁が揃うこと)
- 角丸、余白の刻み、影、罫線の太さもトークンとして決める

## 6. 面ごとの方針

| 面 | 方針 |
|---|---|
| Web の管理画面 | 左に濃色のサイドバー(ホーム、予約ページ、予約、カレンダー、取り込み、連携、設定)。右に作業面。一覧 + 右の詳細パネル。幅が狭いときはサイドバーを畳む |
| 予約ページ(ゲスト) | 中央寄せの 1 枚。左にホストと内容、右に月カレンダーと時間枠。スマホでは縦に積み、日付 → 時間 → 入力の順に進む。ゲストは初めて見る人なので、迷う要素を置かない |
| 取り込み画面 | Slotto の独自機能。日付ごとにまとめた予定の一覧にチェックを付ける。選択中の件数、一括選択、カレンダーでの絞り込み、「未選択の新着」の表示。選んだ予定が空き時間に効くことが伝わるようにする |
| 紹介サイト | ファーストビューに製品画面を大きく見せる。見出しは短く言い切る。機能紹介 → 使い方 3 ステップ → アプリ限定機能 → 料金 → よくある質問 |
| モバイルアプリ | 下のタブ(ホーム、カレンダー、予約ページ、オートメーション、設定)。ホームは「次の予定」を最上部に大きく。OS の作法(iOS と Android)に沿う |
| オートメーション(アプリ) | 「いつ」→「何をする」を上から順に組み立てる。テンプレートから始められる。実行履歴で成功・失敗が分かる |

## 7. 部品

ボタン、入力欄、選択、チェックボックス、スイッチ、タブ、バッジ、アバター、カード、表、リスト行、ダイアログ、横から出るパネル、トースト、ツールチップ、空の状態、読み込み中の骨組み、月カレンダー、時間枠のボタン、週表示のカレンダー、予定のチップ。

状態(通常、ホバー、フォーカス、押下、無効、読み込み中、エラー)を定義する。フォーカスの輪郭は必ず見えるようにする。

## 8. 成果物

1. **デザインシステム**(Claude Design の Design System)。色、書体、余白、角丸、影、部品
2. **画面モック**(Claude Design の Design)。面ごとに 1 つのキャンバス
3. **トークンのコード**(`packages/tokens`)。Web 用の CSS 変数と、アプリ用の TypeScript の値。両方が同じ元から出ること
4. **元ファイル**(`design/`)。アーティファクトの URL の一覧を `design/README.md` に書く

## 9. 確認の進め方

1. 方向の確認: 色と書体の案を 2〜3 個、代表画面(管理画面のホーム、予約ページ、アプリのホーム)で見せて選んでもらう
2. デザインシステムの確認
3. 面ごとのモックの確認(各担当セッションが行う)
4. 実装した画面の確認(各担当セッションが行う)

確認を求めるときは、アーティファクトのリンクを示し、見てほしい点と、選んでほしいことを短く書く。
